# 测试规范

新增或修改业务行为时，先判断应补充或更新哪些测试。测试验证业务结果和边界，不为凑覆盖率测试 getter/setter、框架注解或简单映射。

## 覆盖要求

- 正常流程：有效输入和正常业务状态。
- 异常流程：参数错误、数据不存在、权限不足、状态不允许操作和重复提交。
- 有状态或有金额的核心流程：覆盖状态迁移、事务失败回滚、精度/边界值，以及幂等行为。
- 涉及并发控制、缓存失效或大批量导入导出时，覆盖关键竞争窗口、重复执行或分批失败恢复的可观察结果。
- Service 核心规则优先使用单元测试；需要验证持久化、权限、事务或序列化协作时使用项目现有的集成测试方式。

## 编写原则

- 测试名称描述业务场景和预期结果；准备、执行、断言清晰分段。
- Mock 只隔离真正的外部边界，不 Mock 被测业务逻辑本身。断言可观察的返回值、持久化结果、异常或副作用。
- 测试不得依赖生产数据；测试数据创建可重复执行，并在测试后通过独立事务回滚或清理临时数据。
- 修复缺陷时补上能复现该缺陷的回归用例，除非项目缺少可执行测试基础；此时在交付说明中明确测试缺口。
- 运行构建、测试、服务或浏览器验证前，遵循当前任务的授权范围；未获授权时完成代码与静态检查，并明确说明未运行的验证。
