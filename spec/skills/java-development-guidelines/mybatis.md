# MyBatis、SQL 与数据库变更

SQL 只负责正确、高效的取数与写数：筛选、关联、排序、分页、聚合、空值处理和完整性约束。业务决策、权限结论和展示语义留在 Java。

## Mapper 选择

- 单表新增、修改、删除和简单条件查询可使用 MyBatis-Plus `BaseMapper`。
- 多表关联、多条件动态查询、复杂统计、大量字段映射或需要精确执行计划控制时，使用 Mapper XML，并同步维护 Mapper 接口、参数类型和结果映射。
- 禁止在 Service 中堆叠超过业务可读性的 `lambdaQuery().eq().in().like().orderBy()...`；将查询语义收敛到 Mapper 方法和 XML。

## SQL 规则

- 禁止 `SELECT *`；显式选择字段，并为跨表同名字段写清别名。
- 禁止用 `CASE WHEN` 生成业务状态、状态中文名、权限结果或页面标签；返回原始字段，在 Java 的枚举、字典或 Assembler 中处理。
- 禁止在 SQL 拼接姓名、标题、地址、提示文案等展示字段，禁止把“当前用户能否操作”写成 SQL 决策。租户和数据范围复用项目统一机制。
- 值参数一律优先 `#{...}`。`\${...}` 仅能用于经过固定白名单映射的表名、列名或排序方向，绝不能直接使用用户输入。
- 动态排序字段必须映射到固定白名单。复杂查询显式定义 `resultMap`，处理字段别名和类型。

## SQL 可维护性

- 复杂 SQL 按公共字段、`resultMap` 和有业务语义的 `<sql>` 片段拆分；不要复制大段列清单或在一个 XML 方法中堆叠不可读的动态分支。
- 复杂业务优先在 Java 侧以明确步骤实现，不能通过不断增加 SQL 分支、嵌套子查询或展示字段拼接逃避建模。

## 分页与性能

- 所有列表查询先评估数据量、索引、`count` 成本、关联数量和排序字段；不以“小数据测试正常”替代评估。
- 禁止深分页，例如 `LIMIT 100000, 20`。大表或百万级数据优先评估游标分页、主键分页或时间范围分页，并确认查询计划能使用合适索引。
- 只在 SQL 下推集合聚合和可索引的筛选。涉及多条业务规则、跨系统数据、展示映射或复杂权限时，先取原始数据，再在 Java 侧批量组装。
- 新增或显著修改 `WHERE`、`JOIN`、`ORDER BY` 和唯一业务键时评估索引及写入成本；禁止为查询方便给所有字段加索引。

## 数据库变更

- 结构变更放到项目约定的正向迁移目录，包含表、字段、索引、约束和必要的数据回填；不得依赖先手工改库。
- 新增字段前确认其业务需求和现有表结构；逐项确认并按实际影响同步处理 migration、Entity、Mapper 或 Mapper XML、BO/VO，以及前端字段、类型和展示/提交契约。缺少字段定义或迁移依据时，禁止先写依赖该字段的代码。
- 新字段评估默认值、空值、回填、索引、数据量和滚动发布兼容性。删除或收紧约束前先确认线上数据和发布顺序。
- 新增业务表时复用项目的审计字段和自动填充机制，确认创建人、创建时间、修改人、修改时间和逻辑删除标记；不得另起一套字段名或重复实现审计逻辑。
- 删除业务数据前确认物理删除还是逻辑删除。存在历史、审计或关联关系的数据优先使用项目逻辑删除机制，禁止绕过 `BaseEntity` 等基类的自动填充和删除约定。
- 修改 Mapper XML 时确认运行时加载资源不是旧的编译产物或历史 JAR；具体项目排查经验按需读取 [references/fund-admin.md](references/fund-admin.md)。
