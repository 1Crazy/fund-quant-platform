# REST API 与前后端契约

REST 规范主要约束新增接口。已有模块已经形成稳定路由约定时优先保持一致，禁止仅为形式重写稳定接口路径，例如后台管理模块的 `/list`、`/add`、`/edit`、`/remove`、`/export`。

## 路由与响应

- 查询使用 `GET`，创建使用 `POST`，完整更新使用 `PUT`，部分更新使用 `PATCH`，删除使用 `DELETE`。新接口避免 `POST /deleteUser` 这类动作式路由；优先 `DELETE /users/{id}`。
- 禁止 Controller 直接返回 `Map`、`Object` 或 Entity。沿用项目统一响应类型，不为单个接口临时发明包装结构。
- 列表接口使用项目统一分页对象、字段命名和响应结构；同一模块禁止混用多套分页语义。设置并校验最大页大小，不允许客户端传入如 `size=100000` 的无界请求。
- 列表接口明确排序白名单和空结果语义；不要无边界返回全量数据。
- 使用 MyBatis-Plus 或分页插件排序时，确认字段经过项目已有防注入和白名单处理；禁止把前端的 `orderByColumn`、`sortOrder` 或等价参数直接拼接到 SQL。
- 管理后台列表由 Controller 传入统一分页对象并返回统一分页响应；不要直接调用 `list` 查询后返回全部数据。Service 不暴露原始持久化分页类型，除非项目已有稳定的业务封装约定。
- 导出与列表不能简单复用会一次加载全量对象的查询方法；导出处理遵循 [excel.md](excel.md) 的分批规则。
- 错误码、HTTP 状态、VO 字段类型和枚举值复用项目约定，不能为单个接口临时发明响应格式。

## 兼容性与联调

- 修改已发布接口前，检查前端、其他服务、脚本和公开调用方。禁止未确认调用方就删除字段、改变字段类型、字段含义、枚举值范围、空值语义或分页结构；例如不能直接把既有 `Integer` 状态码改为 `String` 枚举。
- 新增字段默认保持旧调用方兼容；确需不兼容变更时，设计明确版本、迁移或灰度路径，并说明影响范围。
- 改接口时同步核对请求 BO、响应 VO、字段类型、可选性、枚举值、分页结构、错误码和权限标识。禁止只改后端而忽略前端契约。
- 只暴露调用方所需字段；敏感字段、内部实现字段和未稳定的实验字段不进入公共 VO。
- 新增接口补充项目既有 API 文档注解或描述，说明用途、参数、返回结构和必填字段；禁止为了省事删除已有接口文档。
- 内部管理接口默认沿用当前版本和路由约定；公共接口、第三方接口或需长期维护的接口在新增时定义版本策略。禁止通过修改已有字段含义完成隐式升级。
