# 代码生成器

使用代码生成器生成 Java 代码时，生成结果只是起点，不是可直接提交的业务实现。

- 生成目录、包名、模型后缀、Controller/Service/Mapper 结构必须符合当前模块已有约定；不要为了生成器输出引入平行架构。
- 禁止直接覆盖已有业务代码、手工定制的 Mapper XML 或模型。先比较差异，保留已存在的业务规则和兼容性处理。
- 不直接修改自动生成文件，除非项目约定要求；优先修改生成模板或扩展点。`target/`、编译产物、缓存文件等生成物禁止提交；修改模板前评估对既有生成模块的影响。
- 生成后逐项检查权限与数据范围、租户、字段映射、校验分组、分页、审计字段、业务规则和接口契约；缺失的业务逻辑必须按本 Skill 的对应专题补齐。
- 不把生成器产生的通用 CRUD 当作复杂流程、批量操作、导入导出或状态机的最终实现。
